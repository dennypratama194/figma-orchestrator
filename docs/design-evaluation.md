# Visual evaluation protocol

These are evaluation scenarios, not completed tests or approved reference designs. Run them in fresh Figma files with explicit file targets and the host's current Figma capabilities.

1. Industrial equipment supplier: technical credibility, real product photographs, clear specification comparison and quote request. Fail for invented machinery imagery, SaaS dashboard filler or generic glow.
2. Photographer portfolio: images drive the narrative, deliberate crops and typography, restrained navigation. Fail for identical card rhythm inherited from the industrial brief or unreadable text over images.
3. Cafe operations dashboard: task speed, dense readable data, cash/stock/error states and touch interaction. Fail for editorial effects that hide operational information.

For each: inspect actual desktop and mobile screenshots, compare scope to node inventory, verify components and variables through MCP, and test a changed brief after approval. Record accepted/rejected references, rationale, actual time/cost where available, unresolved findings, and the user's decision. No universal numeric taste score replaces this evidence.

For a shader pilot: create one concept-led fill or effect, verify its actual application to a layer, inspect a static fallback, and test the exported runtime in the intended framework. Until this runs, shader support is an authored workflow, not a verified integration.
